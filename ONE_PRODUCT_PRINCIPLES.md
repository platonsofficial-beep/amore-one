# ONE Product Principles

Version: 1.0

---

# Our Mission

ONE is not just a scheduling application.

ONE is the operating system for hospitality businesses.

Our goal is to help managers run their business with confidence by providing the right information at the right time.

ONE never replaces the manager.

ONE makes the manager better.

---

# Product Philosophy

## Manager First

Every feature must solve a real operational problem.

We never build features because they look impressive.

We build features because they save time, reduce mistakes or improve decision making.

---

## Context over Decisions

ONE provides context.

The manager makes the decision.

Never force recommendations.

Never automate critical business decisions without user approval.

Good:

Reservations today: 148

Labour Hours: 82

Last Friday: 151 guests

Bad:

"You should schedule another bartender."

---

## No Fake Data

Never invent data.

If data is unavailable, display:

Not connected yet

or

No data available

Never display fake revenue.

Never display fake reservations.

Never display fake staff.

---

## Dashboard First

Every module must feed the Operations Dashboard.

The dashboard is the first screen managers should open every day.

Every dashboard card must answer an operational question.

---

## ONE Remembers

ONE learns the business.

Not by replacing the manager.

By remembering previous weeks.

Previous reservations.

Previous staffing.

Previous revenue.

Previous notes.

Business history is one of ONE's greatest strengths.

---

## Brand Intelligence

Businesses should feel unique.

ONE should remain recognizable.

Business branding affects:

Buttons

Highlights

Progress bars

Accent colors

Charts

ONE branding remains:

Layout

Typography

Spacing

Navigation

Interactions

Default mode:

ONE Premium

---

## Premium Simplicity

Every screen should feel simple.

Never overload the interface.

If a feature requires three clicks but can be completed in two,

improve the design.

---

## Real Time

The Dashboard should always display live operational information.

No manual refresh.

No stale data.

Live updates whenever possible.

---

## Read Before Write

Dashboard should observe.

Scheduling should modify.

Reports should summarize.

Analytics should explain.

Each module has one responsibility.
